# ClothMatics Website Engineering Reference

Last verified against code: 2026-09-11

This file is the canonical maintained reference for the separate ClothMatics website workspace. The website and mobile app remain separate projects; do not copy implementation claims between them without verifying the website code.

## Inspection contract

- Start with `src/volume` and only files directly referenced from it when that path exists.
- If `src/volume` is absent, report that fact and inspect only the exact feature files needed for the current request.
- Do not scan unrelated directories or re-index the whole repository for a small task.
- Use Context7 only when current library or API documentation is required.
- After every material website code change, update this file with behavior actually implemented and the narrow set of source files involved.
- Never record credentials, access tokens, Firebase ID tokens, private keys, admin PINs, or production secrets here.

## Cross-platform contract

- Mobile application behavior is documented in `D:/stylemateai/StyleMateAI/AGENTS.md`.
- Shared Cloudflare, Firebase, Oracle, extraction, consent, quota and wardrobe behavior must be verified in both codebases before claiming parity.
- Website deployment and mobile deployment remain independent.

### 3D Ghost Mannequin for saved garments

- Wardrobe cards and garment details expose **3D Ghost Mannequin**. Once generated, the same wardrobe item shows a **Normal / 3D** image switch on both surfaces; the saved 3D view is selected immediately after generation. The original `image` and its object key stay unchanged, while **Open 3D studio** retains comparison and download access.
- `ghost-ui.mjs` opens an original/generated comparison dialog, runs technical Gemini analysis through the existing authenticated AI gateway and shared allowance, calls generation, uploads the result to the existing owner-scoped R2 upload route, and automatically saves it to the same wardrobe document.
- `ghost-mannequin.mjs` validates Gemini's category and description. Supported categories are shirt, tshirt, trackpants, trousers, cargo, hoodie, jacket, dress and shorts. Unsupported garments receive an explicit message. The source is the existing wardrobe item's `image`, not a potentially multi-person/full-outfit `sourceImageUrl`.
- `GHOST_ANALYSIS_PROMPT` requires Gemini to condition FLUX on the same garment and exact observed fabric, cut, closures, pockets and letter-for-letter graphics. Gemini describes base, secondary, trim and print colors with approximate sRGB hex values when reliable while declaring source garment pixels authoritative. The generated prompt forbids recoloring and white-balance shifts, requires empty neck/sleeve/waist/hem cavities, limits any inner collar to thin garment fabric along its edge, and treats any neck cylinder, stump, support form, torso/body silhouette, head or skin as invalid. The prompt stays below 4,000 characters. `_headers` serves both Ghost modules with `Cache-Control: no-store` so browsers receive prompt updates immediately.
- `buildGhostAnalysisFromItem` maps saved title, category/subcategory/role, primary and secondary colors, material, non-solid pattern, fit, neckline, sleeves and AI description into the same strict FLUX conditioning contract. It also tells the generator to sample the supplied garment pixels directly and preserve hue, saturation, brightness, undertone, print colors and white balance. `ghost-ui.mjs` uses this path immediately when `aiDescription`, `subCategory` or `material` exists, so auto-extracted and analyzed single-garment wardrobe items do not call Gemini again or consume another quota unit. Only legacy/manual items with none of those metadata fields use `analyzeGhostGarment` as a fallback.
- `functions/api/wardrobe/ghost.js` implements authenticated same-origin GET source/download and POST generation. Each request reads the specific Firestore garment and verifies ownership. Stored image sources are limited to HTTPS R2/Firebase/Google Storage hosts. Cloudflare fetches use the supported `redirect: manual` mode and reject any 3xx source or generator response after inspecting its status. No caller-supplied image URL or generator URL is accepted. Firebase tokens are never forwarded to the generator.
- Cloudflare Pages environment variable `GHOST_MANNEQUIN_API_URL` selects the HTTPS generator endpoint. It safely accepts either an origin or the full `/generate` URL, normalizes both to one `/generate` path, and rejects credentials, query strings, fragments and all other paths. Production and the source fallback use `https://clothmatics-ghost.chiragsharma376.workers.dev/generate`; POST sends `image`, `category`, and `prompt`. `wrangler.toml` does not duplicate this dashboard-managed binding because Cloudflare rejects duplicate Pages Function bindings. The public `config.js` records the service location, but generation uses the server environment. No mobile build change is needed.
- A GPU 429 waits according to a bounded retry delay (15 seconds by default, honoring a safe 5-20 second `Retry-After`) and retries at most six times with fresh multipart bodies. This covers the period where a prior timed-out GPU request still owns the single-worker lock. A Cloudflare 524 caused by GPU cold-start receives exactly one delayed server-side restart; any intervening 429 responses use the same bounded wait. A second 524 returns an explicit warm-up timeout message, and a 429 after exhausting the wait returns a clear busy message. Successful responses expose `X-Ghost-Generation-Attempts`. A user retry retains successful Gemini analysis, and retry-save retains the generated blob rather than spending another generation. A 360-second server timeout bounds retrieval, waiting and generation. Closing during processing aborts the browser request; once persistence starts, closing is disabled until saving finishes. Duplicate requests in the same page are suppressed.
- Cloudflare origin statuses 502, 503, 520-523, 525, 526 and 530 are normalized to `backend_offline` with a clear instruction to restart the Kaggle backend connection. This replaces the generic generation failure for an expired Quick Tunnel while keeping the website-only integration boundary.
- Binary output must have PNG MIME/signature, at least 500 bytes, at most 20 MB and decodable dimensions at least 64x64. Original resolution is retained for download and for storage when within the existing 6 MB upload limit. Larger outputs receive a maximum-2400-edge WebP encode before storage.
- Firestore `ghostMannequin` stores `image`, `imageObjectKey`, `sourceImage`, `category`, `prompt`, `kind: ai_generated`, and server `createdAt`. A transaction rejects deleted, foreign, changed-source or already-generated garments; it updates only this additional field. Failed persistence attempts clean up the new upload where possible. Website garment deletion also attempts generated-object cleanup.
- The dialog labels the result as AI-generated and provides download plus original/3D comparison. Saved downloads use the authenticated same-origin route to avoid storage-host CORS dependencies.
- Validation: all 88 Node tests pass. Ghost coverage includes reusable wardrobe metadata, every supported category mapping, strict source-color and empty-cavity FLUX conditioning, saved Normal/3D image selection with an original fallback, analysis fallback, ownership, full-endpoint normalization, multipart fields, token isolation, supported Cloudflare redirect handling, explicit 3xx rejection, delayed 524 recovery, bounded 429 recovery/exhaustion, Cloudflare origin-offline normalization, invalid output, download selection and original-preserving save guards. The current stable Worker reported its replacement GPU target online. A controlled request was accepted and remained in inference past 45 seconds; a second request was also accepted after the first client timeout, confirming that client/proxy timeouts can outlive or release the server lock at different times and require bounded waiting rather than an immediate retry.
- Metadata reuse, strict invisible-support and color conditioning, wardrobe Normal/3D switching, explicit backend-offline handling and bounded busy recovery are deployed through the Cloudflare Pages `main` branch. The configured stable Worker manages the temporary GPU tunnel target, which must be re-registered whenever Kaggle creates a new Quick Tunnel.

### Garment extraction and mobile parity

- Primary files: `garment-upload.mjs`, `production-extraction.mjs`, `browser-extraction.mjs`, `app.js`, `assets/extraction/`, and `functions/api/wardrobe/extract.js`.
- Style Check uses the same full-outfit prompt and generation configuration as mobile `buildOutfitPrompt`/`analyzeOutfit`: width 1024, JPEG 0.8, temperature 0.2, topP 0.9, 8192 output tokens. A UID-scoped v9 SHA-256 image cache reuses analysis for six hours; `fresh:true` requests fresh analysis. Single Garment premium metadata now uses that same prompt and first garment, rather than a separate single-item prompt.
- Each extraction action verifies `users/{uid}.subscription` through `getDocFromServer`. Only `plan: premium` with a future `premiumUntil` enables Oracle. Free, expired and unverified subscriptions use browser extraction. Free Single Garment does not spend an AI call; metadata remains editable. Auto Extract/Style Check still use the shared authenticated AI allowance.
- Browser extraction runs the mobile U2NetP/MODNet models and transpiled mobile postprocessing in a dedicated module worker. The normal worn entry point uses the mobile person-first legacy pipeline, including visibility, fabric recovery, ownership, footwear seams and geometry gates. `mobile/source-manifest.json` records source hashes. `build-mobile-extraction.cjs` regenerates the pure algorithms from the mobile repository; browser decode/PNG output, inference and diagnostics have explicit adapters.
- Verified model weights are split into files under 8 MiB and SHA-256 checked before inference. ONNX Runtime Web 1.22.0 uses WASM and one thread. Assets are same-origin and fetched lazily; no additional background-removal provider is used. Initial single-garment assets are approximately 16 MB; both models plus runtime are approximately 42 MB. Sessions are retained across sequential items and released after two idle minutes. Cancellation terminates the worker; a 180-second local request timeout bounds processing.
- Premium Single Garment tries authenticated Oracle first and then browser extraction on failure. If that still fails, the browser retries a generous 22% Gemini crop where available, then light-fabric preservation. The original selected file remains available for explicit original/cutout review.
- Premium Auto Extract retains successful Oracle regions and fills failed regions through at most one full-context browser batch. Infrastructure failures stop further cloud calls for that photo. Quality rejection stays per region. Hidden/invalid candidates do not independently trigger inference. No cutout is invented when both engines reject it.
- Prepared preview blobs are reused for saving. Upload optimization preserves transparency, caps cutouts at 1000 pixels and originals at 1200, uses WebP 0.88/JPEG 0.82, and applies a second encode at 0.8/0.74 above 1 MB. R2 upload precedes Firestore wardrobe creation; partial saves and cleanup behavior remain in the existing review flow.
- `_headers` permits same-origin module workers and WASM compilation (`wasm-unsafe-eval`), without enabling JavaScript eval or third-party runtime hosts. Preserve the website copy of `assets/extraction/THIRD_PARTY_NOTICES.txt`; mobile notices remain untouched.
- Validation: 71 Node tests passed, including seven behavioral routing/recovery tests. A real Chromium WASM smoke check ran both models on a synthetic shirt; U2NetP returned a 400x397 PNG and MODNet returned one region. This validates browser execution, not photo-corpus quality parity. Browser/Expo image decoding and encoding can differ; authenticated Gemini/Oracle/R2/Firestore end-to-end and real-photo side-by-side comparison remain separate validation steps.
- Cross-repository tests accept `CLOTHMATICS_MOBILE_ROOT`; without it they use the normal sibling `StyleMateAI` directory.
